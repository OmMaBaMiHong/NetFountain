# 公共库（ip_pool_common）测试计划书

## 1. 测试目标与范围

验证公共库各模块（数据模型、代理测试原语、配置加载、日志、API 通用件）的**正确性、稳定性与通用性**。公共库被三个业务项目依赖，其正确性是全局正确性的前提，测试标准从严。

**范围**：`ip_pool_common/` 下 `models.py`、`testing.py`、`config.py`、`logging_setup.py`、`api.py` 全部公开接口。
**不在范围**：三个业务项目的业务逻辑（见各自测试计划书）。

## 2. 测试环境与工具

| 项 | 说明 |
|---|---|
| Python | 3.14（项目 `.venv`） |
| 测试框架 | pytest + pytest-asyncio |
| 网络桩 | aioresponses（模拟 aiohttp 请求） |
| 覆盖率 | pytest-cov |
| 依赖文件 | `requirements-dev.txt`：`pytest, pytest-asyncio, pytest-cov, aioresponses` |

## 3. 测试层级

| 层级 | 说明 |
|---|---|
| 单元测试 | 各模块纯逻辑，全部网络交互打桩，不依赖真实外网 |

## 5. 测试桩与 Fixture 设计

- `conftest.py`：
  - `event_loop`：session 级事件循环
  - `mock_session`：基于 `aioresponses` 的 aiohttp 桩，统一控制代理/站点响应
  - `tmp_yaml`：临时配置文件 fixture
- 桩对象：
  - 正常 http 代理（200）、鉴权代理（407）、拒绝（ConnectionError）、超时（TimeoutError）
  - socks4/socks5 正常/拒绝应答字节流

## 6. 覆盖率目标

| 模块 | 目标 |
|---|---|
| models / api / config | 100% |
| testing | ≥ 95% |
| logging_setup | ≥ 80% |
| 整体 | ≥ 90% |

## 7. 执行方式

```bash
# 安装依赖
pip install -r requirements-dev.txt
pip install -e ../common

# 运行全部测试 + 覆盖率
pytest -v --cov=ip_pool_common --cov-report=term-missing

# 仅运行某模块
pytest tests/test_testing.py -v
```

## 8. 缺陷管理与退出准则

- **缺陷分级**：P0（阻断，影响三项目）必须修复并复测通过；P1（重要）需修复；P2 可排期。
- **退出准则**：P0/P1 缺陷清零；整体覆盖率 ≥ 90%；全部用例通过后方可发布公共库新版本。
- 公共库改动需在三个业务项目上跑通各自测试（回归）后方可合入。
